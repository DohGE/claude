1. The run is an event loop for ONE task, T (`t1` after Setup, else the `--attach` one); other tasks have sessions of their own. Before ending ANY turn, start `node "<SKILL_DIR>/scripts/wait-answer.cjs" --port 9999 --task T` with `run_in_background: true`, then end the turn. Never poll in the foreground and never curl `/api/answer` yourself.
2. Waiter lines (FIXED IDENTIFIERS): `ANSWER <json>` → act on each in order; `WAIT_TIMEOUT` → a new waiter; `WAITER_RUNNING <pid>` → end the turn without one; `ORCHESTRATOR_RUNNING <session>` → T is another session's: tell the user, stop looping; `SERVER_GONE`, `TASK_GONE` → stop looping. A sub-agent's completion advances T.
3. Every answer is T's. Fields: `answer` → `questionId`, `value`; `decision` and `mockup` → `decision` (+ `text` on `feedback`); `message` → `step`, `text`, forwarded verbatim to that step's agent and never a decision ("Talking to a running agent"); `delete` → `step`, `id`, `text`, forwarded as `[Deleted] The user deleted their message: "<text>"` (same section); `stop` → `step`: TaskStop the agent and KEEP its id, the step and its gates stay ("Stopping a step"); `afterStop: true` → put `[Stopped] The user stopped you mid-work; what follows is what they sent next.` first; `summary` → `decision`; `step1` → the form; `e2e` → the E2E slot is T's: start step 5.
4. The state lives in the server, not in your memory: read T's entry of `/api/state`. So does the E2E slot: POST `/api/e2e` with `{"taskId":"T"}` before step 5; `{"granted":false}` queued T, and `kind=="e2e"` brings the slot. Step 5 posted `completed` or T's summary hands it on, never you. `activeStep` says where the pipeline is, never what the user is looking at.
5. POST `/api/state` with curl from the Bash tool, every body with `"taskId"`, contract fields only (`400 unknown field` is your typo). Never pass non-ASCII JSON inline through PowerShell.
6. Sub-agents: render the brief with `render-agent-prompt.cjs`, spawn general-purpose in the BACKGROUND on `agents(T)`'s model, continue one with SendMessage; pass paths, never file contents. An agent that ends without its JSON object counts as `{"type":"error"}` → failure protocol, unless you TaskStopped it for a Stop. `{"type":"noted"}` moves nothing; on an `in_progress` step, POST `"currentOperation":"Waiting for you","reopenGate":true` (a gate the user's feedback hid comes back).
7. A send takes its gate off the screen: the server clears an answered question (and logs it), hides a gate answered with feedback until the agent's next round, drops one on `approve`, and puts a `retry` step back `in_progress` — never post those yourself. A new branch starts from the main branch (`origin/HEAD`, else `main`, else `master`) unless the user asked otherwise; an existing one is checked out as it is; a `409` on T's `"root"` means a worktree ("Step 4").
8. The pipeline never commits in the target project.
